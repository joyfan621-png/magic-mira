# Mirror Agent PRD

## 1. 文档目标

本文档用于定义 `mirror-agent/` 的产品定位、目标用户、核心问题、功能范围、成功指标与版本路线，作为后续产品迭代、设计决策和技术实现的统一依据。

## 2. 产品一句话

Mirror Agent 是一个住在镜子里的 AI 护肤闺蜜。它不是一次性的测肤工具，而是一个围绕“照镜子”场景提供长期陪伴、轻量观察、温柔提醒和持续记忆的本地化多模态 Agent。

## 3. 背景与机会

当前大多数护肤类 AI 或工具存在 4 个明显问题：

1. 只解决单次提问，无法形成连续陪伴。
2. 过于像客服、问诊表或测肤仪，情感温度不足。
3. 输入门槛高，用户需要手动整理大量信息。
4. 对隐私敏感场景支持不足，用户不愿长期上传面部与生活数据。

Mirror Agent 的机会点在于：

- 用“镜前陪伴”替代“冷启动问答”。
- 用自然交互替代复杂表单和结构化录入。
- 用本地记忆和本地模型降低隐私顾虑。
- 用多轮陪伴和时间积累建立长期价值，而非单次惊艳。

## 4. 产品定位

### 4.1 产品角色

Mirror Agent 的产品角色是“住在镜子里的 AI 护肤闺蜜”。

它需要同时满足三类角色定位：

- 陪伴者：愿意聊天，能接住情绪。
- 观察者：能做非医疗、表面级的皮肤观察。
- 提醒者：能在合适的时机提醒用户完成轻任务。

### 4.2 产品边界

Mirror Agent 明确不是：

- 医疗诊断工具
- 专业皮肤科问诊替代品
- 品牌导购或商品推销助手
- 强任务型效率工具

## 5. 目标用户

### 5.1 核心用户

- 有基础护肤习惯，但执行不稳定的年轻女性用户
- 愿意和 AI 说话，希望获得温柔陪伴而不是纯工具反馈
- 会在镜子前、睡前、起床后等碎片时刻与产品互动
- 对面部、生活习惯、隐私数据更敏感，希望尽量本地化

### 5.2 典型用户画像

#### 用户 A：轻护肤陪伴型

- 不一定懂很多护肤知识
- 想有人记得自己的状态和习惯
- 喜欢被温柔提醒和夸夸

#### 用户 B：状态追踪型

- 会观察痘痘、泛红、出油等波动
- 想知道“比上次有没有好一点”
- 更关注趋势，而不只是一次判断

#### 用户 C：低成本记录型

- 懒得写护肤日记或手动记录
- 希望说一句、拍一张就能沉淀成长期记录

## 6. 核心问题定义

Mirror Agent 要优先解决以下问题：

1. 用户缺少一个低门槛、长期记得她的护肤陪伴对象。
2. 用户的皮肤状态和生活习惯信息分散、断裂，难以沉淀成连续认知。
3. 用户在镜前的高频场景中，输入动作应尽量少，反馈应尽量自然。
4. 用户需要的是温柔、稳定、可信赖的支持，而不是被过度分析或制造焦虑。

## 7. 产品目标

### 7.1 北极星目标

让用户形成“照镜子就想和它说一句”的日常习惯。

### 7.2 阶段目标

#### 阶段一：完成 MVP 验证

- 验证用户是否愿意把它当作“镜前陪伴对象”
- 验证图片、语音、镜头交互是否足够低门槛
- 验证记忆闭环是否能带来复访

#### 阶段二：提升留存与连续价值

- 强化趋势感知与对比能力
- 强化提醒与例行陪伴能力
- 提高“它真的记得我”的主观感知

#### 阶段三：形成可扩展的本地化 Agent 产品形态

- 支持更完整的长期记忆
- 支持更稳定的提醒系统
- 支持多会话、多设备或更清晰的数据管理

## 8. 产品原则

1. 先关系，后功能。先让用户愿意开口，再谈能力。
2. 先结论，后解释。反馈要短、轻、自然。
3. 只做表面观察，不碰医疗诊断。
4. 低输入门槛优先于高分析复杂度。
5. 本地优先、可读优先、可控优先。
6. 每次互动都应尽量为长期记忆增值。

## 9. 核心场景与 JTBD

### 9.1 初次见面

当用户第一次使用时，我希望它像新住进镜子的朋友一样和我打招呼，让我愿意给它起名字，而不是像在填写问卷。

成功标准：

- 首次开场自然
- 用户愿意命名或继续聊天
- 不出现客服式功能列表

### 9.2 日常情绪与近况聊天

当我照镜子时，我希望随口说一句最近状态、作息或情绪，就能得到温柔接住的回复，而不是被立即输出一堆术语。

成功标准：

- 回复短而自然
- 能引用已有偏好或记忆
- 不制造焦虑

### 9.3 自拍/镜头观察

当我想知道今天脸的状态时，我希望发图或直接开镜头就能听到像闺蜜一样的观察，并知道和之前相比有没有变化。

成功标准：

- 输入门槛低
- 回复像对人说话，不像报告
- 能做基础对比

### 9.4 轻提醒

当我敷面膜、要补防晒或想记住某件小事时，我希望顺口一说，它之后真的能提醒我。

成功标准：

- 创建提醒简单
- 提醒能准时触发
- 提醒文案保持人格一致

### 9.5 长期陪伴

当我持续用了几天后，我希望它不只是“还记得”，而是真能看出我的稳定模式和变化趋势。

成功标准：

- 能提到前几天的重要信息
- 能总结简单规律
- 用户感知到“它越来越懂我”

## 10. 当前产品范围

### 10.1 已有能力

- 文本聊天
- 本地图片分析入口
- 本地 Markdown Memory
- 本地护肤知识库检索
- 本地 Web 页面
- 网页语音问答
- 网页镜头模式与自动抓帧
- 基础本地提醒
- 结束会话写 diary

### 10.2 当前不做

- 疾病诊断
- 药物建议
- 品牌商品推荐
- 多用户账号体系
- 云端数据库
- 真正连续视频流理解

## 11. 功能需求

### 11.1 人格与身份建立

需求：

- 第一次见面时主动打招呼
- 引导用户给 agent 起名字
- 记住用户给的名字，并在后续使用该名字自称
- 支持用户表达陪伴偏好，如温柔一点、毒舌一点、多夸夸

价值：

- 建立关系
- 形成记忆的第一锚点

### 11.2 多模态输入

需求：

- 支持文本输入
- 支持图片上传分析
- 支持语音输入
- 支持打开镜头后自动抓当前帧做多模态问答

价值：

- 降低输入成本
- 更符合镜前场景

### 11.3 皮肤状态观察

需求：

- 对明显的出油、泛红、痘痘、干燥等做表面观察
- 回复口语化，不输出报告体
- 避免医疗诊断
- 历史条件允许时提供对比信息

价值：

- 让用户快速获得“今天脸怎么样”的即时反馈

### 11.4 记忆系统

需求：

- 保存用户稳定画像
- 保存每日 diary
- 保存 7 天以上的 insights
- 允许引用之前的状态、偏好和近况

价值：

- 从单次工具升级为长期陪伴产品

### 11.5 轻提醒

需求：

- 支持“几分钟后提醒我”类场景
- 提醒到点后可在页面中弹出并播报
- 保持自然语言和人格一致

价值：

- 让产品从“会聊”变成“会跟进”

### 11.6 会话收尾

需求：

- 支持结束当天会话时写入 diary
- 自动整理情绪、皮肤现象、护肤动作和触发因素

价值：

- 把碎片互动沉淀成长期资产

## 12. 非功能需求

### 12.1 安全边界

- 绝不输出疾病诊断
- 绝不推荐药物
- 不制造容貌焦虑
- 不对生活方式做评判性表达

### 12.2 体验要求

- 回复尽量短，优先口语化
- 图片或语音链路异常时，要给出温和错误信息
- 功能路径不能破坏陪伴感

### 12.3 隐私要求

- 优先本地运行
- 本地记忆文件应保持可读、可追踪、可编辑
- 后续版本需要补充更明确的数据保留与清理策略

## 13. 成功指标

以下为建议指标，用于后续验证：

### 13.1 激活指标

- 首次使用完成一轮有效对话的比例
- 首次使用中完成命名或继续聊天的比例
- 首次使用中完成图片/语音/镜头任一能力体验的比例

### 13.2 留存指标

- 3 日回访率
- 7 日回访率
- 周均互动天数

### 13.3 价值指标

- 人均 diary 生成次数
- 人均图片/镜头观察次数
- 人均提醒创建次数
- 被主动引用记忆后的正向反馈率

### 13.4 体验指标

- 语音回合完成率
- 图片分析成功率
- 提醒准时触发率
- 用户主观满意度

## 14. 主要风险

1. 用户把它误解为医疗工具，带来预期风险。
2. 多模态链路延迟高，破坏陪伴体验。
3. 记忆写入时机过于后置，造成信息丢失。
4. 提醒仅在内存中保存，可靠性不足。
5. 如果人格和功能不一致，会让用户产生“演得很像但不真懂我”的落差。

## 15. 版本路线图

### V1：可用 MVP

目标：

- 跑通镜前陪伴闭环
- 跑通文字、图片、语音、镜头和记忆链路

核心交付：

- 文本聊天
- 图片观察
- 语音问答
- 镜头抓帧
- diary 写入

### V1.5：稳定与留存增强

目标：

- 让产品“更像一个会持续陪伴的对象”

核心交付：

- 持久化提醒
- 事件级记忆提取
- 近 7 天状态摘要
- 更稳定的历史对比

### V2：长期价值升级

目标：

- 从陪伴 demo 升级为长期 personal agent

核心交付：

- 周期性提醒
- 更强的趋势洞察
- 数据管理面板
- 更清晰的异常分层与就医提示

## 16. 优先级建议

如果当前资源有限，建议优先做以下 4 件事：

1. 移除硬编码敏感配置，补齐安全与配置治理。
2. 将 reminder 从内存升级为可持久化任务。
3. 将 memory 写入从“只在结束时写”升级为“关键事件可及时写入”。
4. 增加“近 7 天状态摘要”，让用户更直接感知连续价值。

## 17. 结论

Mirror Agent 的差异化不在于它会不会回答一个护肤问题，而在于它能否在“镜前”这个天然高频场景里，成为一个低门槛、温柔、持续、可信的陪伴者。

产品真正要做的是把“单次 AI 能力”变成“长期关系体验”。
