# 镜子虾外接摄像头优先设计文档

## 背景

当前网页端已经支持打开摄像头并进入自动语音回合，但前端仍然使用：

- `getUserMedia({ video: true, audio: false })`

这意味着浏览器只会打开系统默认摄像头，不能稳定优先使用用户当前接入的外接摄像头 `1080P USB Camera`，页面上也看不到当前实际使用的是哪一个设备。

## 目标

这次调整要满足以下要求：

- 打开镜头时优先使用外接摄像头 `1080P USB Camera`
- 如果外接摄像头不存在，则自动回退到系统内建摄像头
- 页面上显示当前实际使用的摄像头名称
- 如果正在使用的外接摄像头断开，页面自动切回可用的内建摄像头继续工作
- 保持现有视频预览、自动语音回合、抓帧上传能力不变

## 方案选择

### 方案 A：前端设备枚举后按名称优先匹配（推荐）

优点：

- 完全基于浏览器标准媒体设备 API
- 改动集中在现有前端摄像头生命周期
- 能直接把“实际使用设备名”同步到页面
- 适合处理设备断开后的自动重新选择

缺点：

- 首次授权前拿不到完整设备标签，需要在拿到权限后再完成精确匹配

### 方案 B：持久化保存外接摄像头 `deviceId`

优点：

- 同一台机器上再次进入页面时可能更快命中目标设备

缺点：

- `deviceId` 不是稳定标识，跨重插或浏览器上下文可能变化
- 仍然需要名称匹配和兜底逻辑

### 方案 C：由后端决定摄像头设备

优点：

- 理论上可以把偏好写进服务端配置

缺点：

- 浏览器最终仍必须在前端调用 `getUserMedia`
- 会增加接口复杂度，但不能真正替代前端选设备

## 决策

采用方案 A，并增加一个轻量增强：

- 在当前页面生命周期内缓存最近一次命中的外接摄像头 `deviceId`
- 下次打开镜头时先尝试该 `deviceId`
- 如果失败，再重新枚举设备并按名称匹配 `1080P USB Camera`
- 最后仍保留 `video: true` 的系统默认兜底

这样可以兼顾首次可用性、外接优先和断线恢复。

## 架构

### 前端设备选择

- 新增一个摄像头设备枚举辅助逻辑
- 先通过 `enumerateDevices()` 读取 `videoinput` 列表
- 优先匹配标签为 `1080P USB Camera` 的设备
- 如果已经缓存过对应 `deviceId`，优先直接按该 `deviceId` 打开
- 外接设备不可用时，回退到系统默认视频输入

### 前端状态展示

- 在摄像头预览区新增一行设备状态文案
- 初始状态显示“当前摄像头：未连接”
- 成功打开后显示实际视频轨道对应的设备名
- 自动回退后同步刷新为新的设备名

### 前端断线恢复

- 监听当前视频轨道的 `ended` 事件
- 监听 `navigator.mediaDevices.devicechange`
- 当外接摄像头在使用中断开时：
  - 停掉旧轨道
  - 重新枚举设备
  - 优先重连 `1080P USB Camera`
  - 找不到时切回系统默认摄像头
- 成功恢复后继续保留自动镜头模式和抓帧能力

## 数据流

打开镜头时：

1. 页面枚举当前可用视频输入设备
2. 先尝试缓存的外接 `deviceId`
3. 若无缓存或打开失败，则按名称匹配 `1080P USB Camera`
4. 若仍失败，则回退到 `video: true`
5. 将得到的 `MediaStream` 绑定到现有预览 `video`
6. 从视频轨道读取设备标签并更新页面文案
7. 继续沿用现有自动抓帧和自动语音回合流程

设备断开时：

1. 轨道结束或设备列表变化触发恢复逻辑
2. 页面停止旧流并重新选择设备
3. 若外接仍不可用，则切到系统默认摄像头
4. 页面更新“当前摄像头”文案并保持会话可继续

## 错误处理

- 浏览器不支持 `mediaDevices`：继续沿用现有报错提示
- 没有任何可用摄像头：提示用户当前没有可用视频设备
- 首次授权被拒绝：提示先给浏览器摄像头权限
- 外接摄像头名称不出现：回退到系统默认摄像头，而不是让功能整体失败
- 断线恢复失败：清理当前镜头状态并给出明确提示

## 测试策略

新增或更新前端契约测试，覆盖：

- 模板中包含“当前摄像头”状态展示区域
- 前端会调用 `enumerateDevices()` 并按 `1080P USB Camera` 优先匹配
- 找不到外接摄像头时会回退到默认 `getUserMedia`
- 前端会把当前设备名称写入页面状态
- 前端会监听设备变化或轨道结束并触发自动恢复

如果项目已有前端行为测试，优先在现有 `test_frontend_contract.py` 中补充断言，避免引入新的测试入口。
