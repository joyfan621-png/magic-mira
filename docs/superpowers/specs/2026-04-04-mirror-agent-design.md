# 镜子虾 Agent 设计文档

## 背景

目标是从零搭建一个可直接运行的 Python 项目 `mirror-agent/`，实现一个叫“镜子虾”的 AI 护肤闺蜜 Agent。首版只做文字交互，但需要保留图片分析能力入口，使用智谱官方 `zhipuai` SDK 调用：

- `GLM-4`：对话、摘要、工具路由
- `GLM-4V`：图片理解与现象级护肤观察

系统记忆使用本地 Markdown 文件，风格参考 OpenClaw：人格、用户画像、日记、跨周期洞察和护肤知识库都存到本地文件中，保证可读、可追踪、可手工编辑。

## 范围

本次交付包含：

- 命令行入口 `main.py`
- Agent 核心循环 `agent.py`
- Markdown Memory 模块 `memory.py`
- 工具定义 `tools.py`
- 配置模块 `config.py`
- 人格文件 `soul.md`
- Memory 初始化文件与目录
- 护肤知识库 `knowledge/skincare.md`
- 最小测试集和依赖文件

本次不包含：

- 语音输入输出
- Web 前端
- 数据库
- 疾病诊断或商品推荐

## 架构

### 运行方式

用户通过终端启动 `python main.py`。程序在启动时创建 `MirrorAgent` 实例，并做以下初始化：

1. 读取 `soul.md` 作为系统人格
2. 读取 `memory/profile.md`
3. 读取 `memory/insights.md`
4. 读取最近 3 天 diary
5. 组装 Memory 上下文
6. 初始化智谱客户端和工具注册表

会话过程中，用户可以：

- 直接输入普通文本聊天
- 输入 `/image <图片路径> <补充描述>` 触发图片分析
- 输入 `拜拜` 或 `晚安` 结束会话并触发日记写入

### Agent 循环

每轮对话流程如下：

1. 组装系统消息：人格 + Memory 上下文 + 工具约束
2. 将用户消息发送给 `GLM-4`
3. 若模型返回工具调用请求，则执行对应工具
4. 将工具结果作为 tool message 回填给模型
5. 直到获得最终自然语言回复
6. 将用户与助手消息追加到会话历史

### 工具边界

- `skin_analyze`
  - 输入：本地图片路径、用户补充描述
  - 行为：将图片转成 data URL，调用 `GLM-4V`
  - 输出：只描述可见现象、护肤提醒、何时应建议看皮肤科
- `memory_read`
  - 输入：读取目标和数量限制
  - 行为：从 Markdown Memory 拉取内容
- `memory_write`
  - 输入：完整对话记录和日期
  - 行为：调用 `GLM-4` 总结后写入 diary；必要时更新 profile 和 insights
- `skincare_knowledge`
  - 输入：查询词
  - 行为：对本地知识库做简单关键词检索并返回匹配片段
- `trend_analyze`
  - 输入：最近若干日记
  - 行为：基于本地 diary 汇总趋势，供模型引用

## 数据设计

### `profile.md`

用于长期稳定信息：

- 肤质或明显倾向
- 作息、压力、周期性习惯
- 常见护肤困扰
- 已知禁忌或偏好

### `diary/YYYY-MM-DD.md`

用于每天一页，会包含：

- 今日情绪
- 今日护肤动作
- 今日皮肤现象
- 触发因素
- 镜子虾备注

### `insights.md`

只记录跨 7 天以上才值得沉淀的模式，例如：

- 熬夜与闭口/出油关联
- 经期前泛红规律
- 换季时屏障波动

## 错误处理

- 未配置 API Key：启动时给出明确提示
- Memory 文件不存在：自动初始化
- 图片路径不存在：返回温和错误信息
- 模型调用失败：返回清晰异常并不中断本地数据
- 工具调用异常：返回工具错误文本，再交由模型决定如何回复

## 测试策略

首版使用标准库 `unittest`，覆盖：

- Memory 初始化与读取
- Diary 写入与最近日记读取
- 结束语识别
- 知识库检索的基本行为

外部 API 不做联网单测，而是通过可注入客户端保证核心逻辑可测试。

## 运行说明

项目根目录为 `mirror-agent/`。安装依赖后执行：

```bash
cd mirror-agent
pip install -r requirements.txt
python main.py
```
