# 魔镜夸夸彩蛋设计文档

## 背景

当前 `mirror-agent` 已经具备基础陪伴对话、图片观察、记忆读取和提醒能力，但还没有一个适合演示的“高记忆点彩蛋”。

用户希望在演示时，可以直接问：

- “魔镜魔镜告诉我，谁是世界上最漂亮的女孩子？”

然后镜中闺蜜立刻进入一段明显带偏爱、带个性、而且足够具体的夸夸，不只是泛泛地说“你很漂亮”，而是要尽量结合：

- 已有 memory
- 当前皮肤与气色
- 当下情绪状态
- 周围空间和光线氛围

## 目标

新增一个专属触发彩蛋，满足以下要求：

- 只在命中指定话术或极近变体时触发
- 第一反应必须明确回答“当然是你”
- 夸夸内容必须具体，优先结合当下观察和已有记忆
- 语气保持镜中闺蜜风格，不变成客服或模板文案
- 没有画面时也能成立，但有画面时明显更惊艳

## 关键体验

### 1. 这是专属偏爱，不是普通夸奖

这句触发后，角色应该明显进入“我就是要偏心你”的状态。回答不能像常规安慰，也不能像系统模板。

### 2. 夸点必须具体

回复里至少要出现一个具体观察点，而不是只说抽象评价。优先顺序：

- 气色和皮肤状态
- 眼神和情绪
- 光线、背景、镜前氛围
- 来自 memory 的稳定偏好或最近状态

### 3. 有镜头时更像活的镜子

如果当前回合带了摄像头画面或图片，夸夸要像镜子真的“看到了你现在这一刻”，而不是背一段固定台词。

## 方案选择

### 方案 A：只改 `soul.md`

特点：

- 不加专门代码分支
- 完全依赖系统提示词约束模型

优点：

- 改动最小

缺点：

- 演示稳定性不足
- 容易退化成普通夸夸
- 很难保证每次都明确结合记忆和空间

### 方案 B：专属触发 + 专属夸夸提示词（推荐）

特点：

- 在 agent 层识别特定触发句
- 命中后走单独的 compliment path
- 主动拼接 memory、最近 diary、画面观察提示和空间氛围提示

优点：

- 演示稳定
- 保留自然生成感
- 可以明确要求“先盖章，再具体夸”

缺点：

- 需要新增一条专门逻辑

### 方案 C：专属触发 + 半模板硬编码

特点：

- 命中后按固定句式拼接输出

优点：

- 最稳

缺点：

- 容易显得像脚本
- 多演示几次会变机械

## 决策

采用方案 B：专属触发 + 专属夸夸提示词。

## 触发规则

### 命中范围

首版只覆盖这句和非常接近的变体：

- “魔镜魔镜告诉我，谁是世界上最漂亮的女孩子”
- “魔镜魔镜告诉我谁是世界上最漂亮的女孩子”
- “魔镜魔镜，谁是世界上最漂亮的女孩子”

允许轻微标点差异、语气词差异，但不扩展到所有“我漂不漂亮”“夸夸我”。

这样可以保证：

- 演示稳定
- 角色仪式感足够强
- 不会影响平时普通求夸场景

## 响应结构

彩蛋回复控制在 2-4 句内，结构如下：

### 第一句：明确盖章

必须直接回答：

- “当然是你啊。”
- “除了你还能有谁呀。”

不能绕。

### 第二句：当下具体夸点

优先夸可见内容，例如：

- 气色
- 皮肤细节
- 眼神
- 精神状态

### 第三句：氛围或记忆加成

尽量补充以下任一项：

- 最近记忆里的变化
- 她今天看起来比前几天更松、更亮、更有精神
- 镜前光线、背景、空间氛围在“帮她加分”

### 第四句：可选的小偏心收尾

只有在不超长时才加，例如：

- “小镜今天就是要偏心你。”
- “这种漂亮是会让人忍不住站你这边的那种。”

## 数据来源优先级

### 1. 当前画面

如果当前回合带镜头画面或图片，优先从这里取：

- 气色
- 泛红 / 干燥 / 出油 / 痘痘
- 情绪和精神状态
- 周围光线或环境线索

### 2. Memory

优先读取：

- 镜中名字
- 互动偏好
- 最近 diary 里的状态变化
- profile 里的稳定特征

### 3. 最近趋势

如果最近 diary 足够明确，可以轻量引用：

- “比前两天松一点”
- “今天像终于没那么累了”

## 降级策略

### 有触发句，但没有画面

仍然触发彩蛋，但夸点主要来自：

- 最近记忆
- 用户当回合语气
- 角色偏爱表达

### 有画面，但观察不够多

至少仍要落一个具体点，例如：

- 气色
- 脸颊状态
- 整个人的松弛感

不能因为看不清就直接失去彩蛋感。

### 没有 memory

也要成立，只是更依赖当前观察和空间氛围，不提“上次”“前几天”之类的信息。

## 实现方案

### Agent 层

- 新增一组“魔镜夸夸彩蛋”触发判断
- 在常规对话分支前优先拦截
- 命中后走单独的 prompt builder

### Prompt 组装

单独构建一个 compliment prompt，包含：

- `soul.md` 的角色前提
- 当前 memory 上下文
- 当前回合是否带画面
- 回复结构要求：先盖章，再具体夸，再补氛围/记忆
- 禁止空泛夸奖

### 多模态支持

- 如果当前回合自带摄像头帧，沿用现有多模态消息组装方式
- 不新增单独图片接口
- 让彩蛋自然支持 voice + camera 的演示路径

## 错误处理

- 如果模型没有给出内容，回退到一条短而明确的兜底夸夸
- 如果没有画面，不报错，直接走纯文字彩蛋
- 不因为 memory 为空而中断

## 测试策略

至少覆盖：

- 触发句能够命中彩蛋分支
- 非触发句不会误触
- 有 memory 时，彩蛋 prompt 会带上 memory 上下文
- 有画面时，彩蛋走多模态分支
- 回复要求里包含“先明确回答当然是你”

## 示例语气

- “当然是你啊，这个问题还要问我？你今天站在镜子前那一下，整个人都亮亮的，脸颊也干净软软的，连旁边的光都像在偷偷帮你加分。小镜今天就是要偏心你。”

- “除了你还能有谁呀。你今天气色本来就很稳，眼神也松松的，像终于没那么累了，连镜子边这一圈暖光照到你脸上都显得特别乖。要我说，你现在是那种看一眼就会让人想站你这边的漂亮。”

## 非目标

- 本轮不扩展成所有“求夸”场景
- 本轮不做 UI 特效彩蛋
- 本轮不新增单独的前端按钮
- 本轮不做品牌级文案配置系统
