# 镜子虾 Web 页面设计文档

## 背景

当前 `mirror-agent/` 已经具备可运行的 CLI Agent，包括：

- 智谱 `GLM-4` 对话
- 智谱 `GLM-4V` 图片分析入口
- Markdown Memory
- 本地护肤知识库

这次要新增一个“可交互页面”，让用户可以通过浏览器直接和镜子虾聊天，而不是只在终端使用。

## 目标

新增一个本地 Web 页面，满足以下要求：

- 本地启动，不依赖数据库
- 复用现有 `MirrorAgent` 核心逻辑
- 支持文本聊天
- 支持图片上传后走现有图片分析能力
- 支持一键结束会话并写入当日日记
- 保留原 CLI，不破坏现有用法

## 方案选择

### 方案 A：Flask + 单页 HTML（推荐）

优点：

- 依赖少，开发速度快
- 很适合本地单用户体验
- 直接复用现有 Python Agent
- 文件结构清晰，后续加语音或更多页面也容易扩

缺点：

- 首版前端交互能力有限，不是 SPA 框架

### 方案 B：FastAPI + 原生前端

优点：

- API 风格更规范
- 后续如果要接前端框架会更自然

缺点：

- 对当前需求来说偏重
- 比 Flask 多一层启动和组织成本

### 方案 C：纯静态页面 + 轮询本地脚本

优点：

- 前端看起来最轻

缺点：

- 后端通信会变笨
- 上传图片和会话状态管理都更别扭

## 决策

使用 Flask 做一个本地单页 Web 界面。

## 架构

### 新增文件

- `mirror-agent/webapp.py`
  - Flask 应用和路由
- `mirror-agent/templates/index.html`
  - 聊天页面结构
- `mirror-agent/static/style.css`
  - 页面样式
- `mirror-agent/static/app.js`
  - 前端交互逻辑
- `mirror-agent/tests/test_webapp.py`
  - Web 路由测试

### 路由设计

- `GET /`
  - 返回聊天页面
- `POST /api/chat`
  - 接收用户文本，返回镜子虾回复
- `POST /api/image`
  - 接收上传图片和补充描述，返回图片分析后的镜子虾回复
- `POST /api/end`
  - 结束会话并写入当日日记

### 会话模型

首版是本地单用户页面，因此后端进程里维护一个全局 `MirrorAgent` 实例即可。这样 Memory 和记忆逻辑都可以直接复用，不需要额外的 session 存储层。

## 页面设计

页面要像一个轻量“护肤闺蜜小房间”，不是后台管理台。

包括：

- 顶部标题和一句人格化描述
- 中间聊天消息流
- 底部文本输入框和发送按钮
- 图片上传按钮
- “晚安，写日记”结束按钮
- 状态提示区，显示发送中、报错或写 diary 成功

## 错误处理

- 未填 API Key：页面可打开，但聊天返回清晰提示
- 未选择图片：前端直接提示
- 图片上传失败：页面显示温和报错
- 服务异常：后端返回 JSON 错误，前端展示友好提示

## 测试策略

使用 Flask test client 验证：

- 首页可访问
- 文本聊天接口返回 JSON
- 图片接口在缺失文件时返回 400
- 结束接口会返回 diary 路径

## 运行方式

新增两种启动方式都可以接受：

- `python3 webapp.py`
- 或者在 `main.py` 增加 `web` 参数跳转

为了保持职责清晰，首版选择直接新增 `webapp.py`。
